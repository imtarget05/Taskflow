## Implemented stateless JWT authentication with rotating, hashed, reuse-detected refresh tokens
- **IMPLEMENTATION**: Access and refresh tokens are separate signed JWTs with an enforced `type` claim (`server/src/utils/token.ts:18`, `:30`, `:41`, `:45`). Refresh tokens are persisted only as a SHA-256 hash (`server/src/modules/auth/auth.service.ts:17`, `:29`) and passwords are bcrypt-hashed at cost 10 (`server/src/modules/auth/auth.service.ts:48`). On refresh, a token already marked consumed is treated as a stolen-token replay and revokes **every** session for that user (`server/src/modules/auth/auth.service.ts:91-103`, `revokeAllRefreshTokens` at `:120`). Forgot/reset password reuses the same hashed-token pattern (`:148`, `:176`).
- **FILE**: `server/src/utils/token.ts`, `server/src/modules/auth/auth.service.ts`

## Made a fresh clone buildable by making Prisma code generation a build prerequisite
- **IMPLEMENTATION**: On a clean clone `npm ci && npm run build` failed with 94 TypeScript errors — for example `src/utils/errors.ts(4,10): error TS2305: Module '"@prisma/client"' has no exported member 'Prisma'` and `src/utils/roles.ts(1,10): error TS2305: Module '"@prisma/client"' has no exported member 'Role'` — because the generated Prisma client does not exist until `prisma generate` runs, and nothing in the install or build path triggered it. CI (`.github/workflows/ci-cd.yml:60-62`, `.github/workflows/e2e.yml:30-32`) and the container builds (`server/Dockerfile:18`, `:36`) both ran codegen as an explicit step; the local path did not, so a reviewer cloning the repo saw a red build. The fix moves codegen into the `server` workspace `build` and `typecheck` scripts (`server/package.json:9`, `:11`), so a fresh clone cannot skip it. A root `postinstall` was rejected: `server/Dockerfile:9-12` and `client/Dockerfile:9-12` run `npm ci` against manifests only, before any `server/prisma/schema.prisma` is copied, so a root `postinstall` codegen would hard-fail both Docker builds.
- **FILE**: `server/package.json`
- **TEST**: NOT VERIFIED by a unit test — this is build tooling, verified by a clean-clone build instead.
- **RUNTIME EVIDENCE**: BEFORE — `git clone --depth 1 https://github.com/imtarget05/Taskflow taskflow-freshcheck && npm ci && npm run build` → `npm error Lifecycle script 'build' failed`, exit 2, 94 `error TS…` lines, the first being `src/lib/prisma.ts(1,10): error TS2305: Module '"@prisma/client"' has no exported member 'PrismaClient'`. AFTER — fresh clone of the fixed tree: `npm ci` → exit 0; `npm run build` → `Generated Prisma Client (v5.22.0)`, `2779 modules transformed`, `built in 17.95s`, exit 0, 0 TypeScript errors; `npm run typecheck` → exit 0, 0 TypeScript errors.
